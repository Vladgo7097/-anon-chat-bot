# Правила миграций

История SQL-миграций идентифицируется полным именем файла и checksum.
Применённые 004_* и 005_* не переименовывать: они уже являются разными
версиями. Новый префикс должен быть строго больше всех существующих
префиксов; для новых файлов повторные номера запрещены.

Миграции выполняются только вперёд. Отмена кода не означает удаление
пользовательских данных из схемы. Текущая миграция 007 только добавляет
индексы, совместимые с предыдущей версией приложения; откат кода не требует
отката схемы. Для будущих несовместимых изменений нужны отдельный план
восстановления из резервной копии и проверка совместимости до деплоя.

Не добавлять универсальный DROP или переименование старых миграций ради
формального downgrade. Смена инструмента миграций — отдельная задача.
